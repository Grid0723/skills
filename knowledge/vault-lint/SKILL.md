# vault-lint

只读体检，先出报告再修复。目标是让元数据可统计、状态机可信、标签可聚合。

## Leading Words

| 术语 | 定义 |
|------|------|
| **失败** | 违反硬规则，必须修（缺必填字段、状态非法、坏 frontmatter） |
| **警告** | 建议修（标签格式、重复文件、超期未处理） |
| **建议** | 可选优化（双链、MOC、hub；转交 `connect`） |
| **只改元数据** | 修复只动 frontmatter 与文件名，不改正文内容 |

## 检查范围

```text
00_收集箱/
01_孵化/
10_领域/          （排除 10_领域/编程技术/Agent Skills/Grid/skills）
20_项目/          （仅管理文档：总览/项目计划/外部链接）
```

## 硬规则（失败）

### 1. frontmatter 完整性

必填字段：

```yaml
Author: 张谦
tags: [领域/子主题]
类型: 剪藏 | 永久笔记 | 项目 | 速记 | 想法 | 索引
状态: 待整理 | 已归位 | 已提炼 | 可输出
创建: YYYY-MM-DD HH:mm:ss
修改: YYYY-MM-DD HH:mm:ss
```

例外：

- `类型: 想法` 不设 `状态`（用 `孵化阶段` 代替）
- `类型: 项目` 的状态由项目规范定义（投研独立状态集）
- 剪藏额外需要 `来源`

### 2. 状态机

- 只允许四态：待整理 / 已归位 / 已提炼 / 可输出
- 领域内出现 `待整理` → 失败（应回收集箱或已归位）
- 收集箱出现 `已归位` / `已提炼` → 失败（应移出）
- 禁止自造：`整理中`、`已消化`、`进行中`、`观察`（项目类型除外）

### 3. 坏的 frontmatter

- 一行多字段：`状态: 进行中 | 创建: ...`
- 字段值带不该有的引号：`状态: "待整理"`
- 时间格式非 `YYYY-MM-DD HH:mm:ss`

### 4. 重复文件

- 同名带副本后缀：`<标题> 1.md`、`<标题>(1).md`
- 同一标题出现在不同目录且无主次关系

## 警告

### 5. 标签格式

- 必须层级化：`领域/子主题`（如 `交易/理论`、`技术/AI/Skills`）
- 禁止：`- 技术/git`（列表符号进标签）、`[\\技术/n8n\\]`（转义符）、纯空格
- `tags` 只放主题标签；来源放 `来源`，类型放 `类型`

### 6. 时效

- 收集箱 `创建` 超过 30 天仍 `待整理`
- 投研笔记 `修改` 超过 90 天且 `已归位` → 标"待复核"
- 剪藏超过 90 天仍留在收集箱 → 建议归档

### 7. 织网缺口（转交 `connect`）

- 子标签 ≥3 篇但无 MOC
- 子标签 ≥5 篇但无 hub
- 孤儿笔记（无入链、无出链）

## 报告格式

```text
Vault 体检
- 扫描：800 篇
- 失败：3
- 警告：12

## 失败
- [frontmatter] 10_领域/交易投资/x.md — 缺 状态
- [状态] 00_收集箱/剪藏/y.md — 状态: 已归位（应在领域）

## 警告
- [标签] 10_领域/编程技术/z.md — `- 技术/git`
- [时效] 00_收集箱/剪藏/w.md — 收集 88 天未处理

## 建议
- [MOC] 交易/个股分析/港口 — 27 篇无 MOC（转 connect）
```

## 修复流程

1. **只读扫描**：运行脚本或按检查项逐条扫描，产出报告
2. **用户选范围**：按类别（frontmatter / 状态 / 标签 / 重复）或目录
3. **Dry-run**：列出将改的文件与字段，等确认
4. **修复**：只改元数据；正文不动
5. **复跑**：同一检查项失败数应为 0
6. **提交**：`chore: vault-lint 修复 <类别>`，附数量

## 边界

- 不自动修复，先报告
- 批量修复前必须 dry-run
- 不改正文、不移动文件（移动交 `organize`）
- 织网建议交 `connect`，本 skill 不建 MOC
- 归档目录与 `Grid/skills` 不在扫描范围

## 外部参考

- `scripts/check-vault.ps1` — 只读扫描脚本（frontmatter / 状态 / 标签 / 重复）
- `references/checks.md` — 每项检查的判定规则与修复示例

## Gotchas

- 直接批量改 frontmatter 不 dry-run → 修错无法回滚，先出清单
- 把 `类型: 项目` 的状态当异常 → 项目状态由项目规范定义，跳过
- 只修状态不修标签 → 下次体检仍然失败，按类别一次修完
- 把收集箱的剪藏直接删除 → 先归档或归位，保留原始来源
