# 检查项与修复示例

## 1. frontmatter 必填

| 字段 | 要求 | 例外 |
|---|---|---|
| `Author` | 张谦 | — |
| `tags` | 层级标签列表 | — |
| `类型` | 六类枚举 | — |
| `状态` | 四态枚举 | 想法（用孵化阶段）、索引（可省略）、项目（项目规范） |
| `创建` / `修改` | `YYYY-MM-DD HH:mm:ss` | — |

修复：

```yaml
# 之前
状态: "待整理"

# 之后
状态: 待整理
```

模板里的行内注释属合法写法，脚本会先剥离 `#` 之后的内容再校验：

```yaml
状态: 待整理  # 待整理 | 已归位
```

## 2. 状态机

| 位置 | 允许 | 不允许 |
|---|---|---|
| 收集箱 | 待整理 | 已归位 / 已提炼 / 可输出 |
| 领域/项目 | 已归位 / 已提炼 / 可输出 | 待整理 |
| 想法 | 无状态（用 `孵化阶段`） | 任何 `状态` |
| 项目 | 项目自定义 | — |

修复：

- 收集箱出现 `已归位` → 移出，或回退 `待整理`
- 领域出现 `待整理` → 补 `已归位`，或回收集箱
- `整理中` / `已消化` / `进行中` → 映射到四态或项目状态

## 3. 标签格式

正确（行内数组）：

```yaml
tags: [交易/理论/交易系统, 技术/AI/Skills]
```

块级列表同样支持：

```yaml
tags:
  - 交易/理论/交易系统
  - 技术/AI/Skills
```

错误与修复：

| 写法 | 问题 | 修复 |
|---|---|---|
| `- 交易/理论` | 列表符号混入 | `交易/理论` |
| `\交易/理论\` | 转义符 | `交易/理论` |
| `[\\交易/量化\\]` | 双重包裹 | `交易/量化` |
| `timeline` | 无层级 | 删除，或归入 `工具/时间线` |
| `工具与效率` | 无层级 | `工具与效率/<子主题>` |

## 4. 重复文件

- `<标题> 1.md`、`<标题>(1).md`，且同名原件 `<标题>.md` 确实存在（否则如 `路由器(2025).md` 不报）
- 修复：比对内容，保留主版本，另一份归档或删除；先确认无反向链接

## 5. 时效

| 场景 | 阈值 | 动作 |
|---|---|---|
| 收集箱待整理 | >30 天 | 归位 / 归档 / 删除 |
| 投研已归位 | >90 天未修改 | 标"待复核" |
| 剪藏 | >90 天仍在收集箱 | 归档 |

## 6. 修复批次

建议按类别分 commit：

```text
chore: vault-lint 修复 frontmatter 引号（20 篇）
chore: vault-lint 修复标签格式（N 篇）
chore: vault-lint 处理重复文件（N 组）
```

每批修完复跑脚本，确认该类失败归零。
