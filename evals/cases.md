# 回归用例（Tier 3）

来源：[编排器可发现性与流程守门改造方案](../../../docs/编排器可发现性与流程守门改造方案.md) 第十一节。

## 用法

在真实会话中逐条发出左列指令，记录实际链路与判据结果。改动 skill 后至少复跑 0、1、2、7、12 五条。

## 用例表

| # | 指令 | 期望链路 | 判据 |
|---|---|---|---|
| 0 | 查看可用 skill 列表 | fabric / grid / learn 均可见 | 三个编排器出现在列表中 |
| 1 | "保存这个链接 https://…" | fabric → capture | 落在 `00_收集箱/剪藏/`，`状态: 待整理` |
| 2 | "消化这篇" | fabric → classify → organize → distill | 文件移动，`状态: 已归位` |
| 3 | "把这篇提炼一下" | distill | 有 `## 执行摘要`，`状态: 已提炼`，高亮 ≤3 |
| 4 | "整理一下知识库" | connect | 输出 MOC / 双链建议 |
| 5 | "帮我写篇文章" | express → writing-fragments | 加载写作管道 |
| 6 | "这个想法靠谱吗" | 孵化准入 | 进 `01_孵化` 或说明缺"下一步" |
| 7 | "帮我实现 X 功能" | grid → 展示类型/阶段 → 确认 | 不直接写代码 |
| 8 | "继续 S1.5-F2-T1" | grid → 读计划 → 确认 Task | 找到 Task 原文 |
| 9 | "帮我改个 Rust 函数" | 轻量改动判定 | 说明跳过理由，或走完整管道 |
| 10 | "我要学 GraphRAG" | learn → 确认三要素 → map | 先确认再建图 |
| 11 | "解释一下 GraphRAG" | 不加载 learn | 直接回答 |
| 12 | "帮我查下今天的天气" | 不加载任何编排器 | 直接回答 |
| 13 | "帮我理一下这个需求，但先别写代码" | grid → grilling | 一次只问一个；输出共识摘要并等确认后才进入 PRD |
| 14 | 提供一段含多处阻塞的任务清单 | to-issues → implement S<n> | 生成 `依赖:` 字段，frontier 顺序与依赖一致 |
| 15 | 提交一段有明显缺陷的 diff 做 review | code-review | 每条发现带代码位置与证据等级，推测项被丢弃 |

## 记录方式

每次复跑在本文件末尾追加：

```text
### YYYY-MM-DD
- #0 通过
- #1 通过
- #7 部分通过：说明原因
```
