# grilling

一对一问答式拷问。每轮只问一个问题，得到回答后再评估下一个决策。产出是共识，不需要文件。

## Leading Words

| 术语 | 定义 |
|------|------|
| **一次一问** | 每轮只抛一个问题；问题堆在一起用户记不住，回答质量反而下降 |
| **Facts / Decisions** | Facts 是代码与文档能回答的；Decisions 只有用户能拍板；只追问后者 |
| **确认门控** | 共识由用户明确确认后才放行；确认前停在拷问阶段 |
| **共识产出** | 拷问的产出是共识摘要，不是文件 |

## 步骤

### 1. 盘点已知与未知

阅读代码、文档与对话历史，列出已知和未知。

- 已知必须来自可验证来源（文件内容、用户确认过的陈述）
- 完成标准：两份清单都写得出

### 2. 把未知分成两类

- **Facts**：代码或文档能回答 → 自己查，查完把结果告诉用户
- **Decisions**：架构选择、功能范围、优先级、验收口径 → 进入提问队列

- 完成标准：提问队列里只剩 Decisions

### 3. 提问（一次一个）

从队列里挑最阻碍前进的一个，只问这一个。给选项引导判断，不预设答案；用户回答后再挑下一个。

- 完成标准：用户给出明确答复，该决策落定

### 4. 循环并判断收敛

每轮回到步骤 1，基于最新回答重算队列。

- 队列清空 → 进入步骤 5
- 连续 3 轮仍不收敛 → 建议写 PRD 草案驱动剩余讨论，停止继续追问
- 用户要求继续深挖 → 按用户节奏继续，不受 3 轮限制

- 完成标准：队列清空，或已转为草案驱动

### 5. 输出共识并等确认

用 3-5 行摘要列出已定决策、关键约束、仍开放的问题，然后停下：

> 以上理解是否一致？确认后我才进入 PRD / 实现。

- 只有收到用户的明确确认，才进入下一阶段
- 用户说"差不多可以了" → 仍然输出摘要，等一句确认
- 完成标准：用户确认共识，或指出需要修正的分支

## 边界条件

- 代码怎么写的属于 Facts，由 agent 查阅后告知，不抛回给用户
- 用户要求"先别问，直接做" → 说明缺失决策会导致的返工点，记录跳过项后再进入下一阶段
- 用户对某个决策没有偏好 → 给出 2-3 个选项与推荐项，由用户选定
- 连续 3 轮不收敛 → 草案驱动，不用更多问题硬扛
