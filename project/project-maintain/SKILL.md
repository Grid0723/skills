# project-maintain

项目运行期的两项例行维护：里程碑回顾与外部链接。

## Leading Words

| 术语 | 定义 |
|------|------|
| **里程碑总结** | 总览中的「📝 里程碑总结」区——核心变更、关键决策、所学经验 |
| **阶段切换触发** | 项目阶段变更（启动→进行中→收尾）时自动触发回顾 |
| **file:/// 路径** | 本地文件/文件夹的绝对路径链接 |

## 入口判定

| 用户请求 | 模式 |
|---|---|
| 更新里程碑 / 回顾进度 / 阶段总结 | 回顾模式 |
| 加外部链接 / 整理项目链接 | 链接模式 |

## 回顾模式

### 1. 读取变更记录

- 软件项目：读取 `CHANGELOG.md` 或 `git log`
- Obsidian 项目：读取项目目录下的笔记变更

- 完成标准：变更清单已提取

### 2. 撰写里程碑总结

提取三个维度：

- **核心变更**：本阶段完成了什么
- **关键决策**：做了什么选择及其原因
- **所学经验**：可复用的知识

- 完成标准：三段内容已产出

### 3. 更新总览

写入项目总览的「📝 里程碑总结」区，追加时间戳。

- 完成标准：总览已更新

## 链接模式

在 `20_项目/<项目名>/外部链接.md` 中追加：

```markdown
- [名称](file:///path) — 描述
- [名称](https://url) — 描述
```

所有项目链接由 dataview 聚合于 `20_项目/外部链接.md`。

- 完成标准：链接已追加且描述清晰

## 外部参考

- `references/review-template.md` — 从 CHANGELOG 提取里程碑总结的三步法与模板

## Gotchas

- 回顾时只抄 CHANGELOG 标题 → 必须补「关键决策」与「所学经验」，否则总结没有复用价值
- 外部链接只写 URL 不写描述 → 三个月后无法判断哪个链接对应哪份资料
