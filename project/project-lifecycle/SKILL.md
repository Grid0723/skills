# project-lifecycle

从立项到归档的完整项目流程。回顾与链接维护见 `project-maintain`。

## Leading Words

| 术语 | 定义 |
|------|------|
| **项目总览** | 每个项目至少一篇总览文档——`类型: 项目`，含项目阶段与里程碑 |
| **阶段流转** | 启动 → 进行中 → 暂停 → 收尾 → 完成 → 归档 |
| **功能模块** | 任务按功能分组而非时间线，每个模块独立可验证 |
| **先提炼再归档** | 归档前先提取可复用知识——归档后很少再访问 |

## 入口判定

| 用户请求 | 模式 |
|---|---|
| 新建项目 / 立项 | 启动模式 |
| 拆任务 / 更新项目范围 | 计划模式 |
| 归档项目 / 收尾 | 归档模式 |

## 启动模式

### 1. 收集项目信息

询问项目名称、一句话描述、目标领域。

- 完成标准：基础信息齐全

### 2. 创建目录与总览文档

在 `20_项目/<项目名>/` 下创建 `总览.md`：

```yaml
---
类型: 项目
tags: [项目/<项目名>, <领域标签>]
项目阶段: 启动
---
```

结构：项目目标 / 里程碑总结（初始为空）/ 关联领域。

### 3. 创建外部链接文档

在 `20_项目/<项目名>/` 下创建 `外部链接.md`，维护本地路径（`file:///`）与外部 URL。

- 完成标准：总览与外部链接文档已创建

## 计划模式

### 1. 确认项目范围

读取总览，与用户确认功能范围。

### 2. 生成任务清单

在 `20_项目/<项目名>/` 下创建 `项目计划.md`：

```markdown
## 项目计划: <项目名>

### 模块 A
- [ ] 任务描述 #项目/<项目名>

### 模块 B
- [ ] 任务描述 #项目/<项目名>
```

规则：每个任务用 `#项目/<项目名>` 标签归属；粒度控制在 1–2 个 session 内完成。

> [!warning] 项目计划 ≠ PRD/开发计划
> `项目计划.md` 是项目管理维度的任务清单，**不替代**代码仓库中的 PRD（seam/范围/风险）与开发计划（tracer bullet 切片）。进入编码仍须走 Grid 完整流程：拷问 → PRD → 拆 Issue → 编码；本计划仅作为拷问的输入素材。

- 完成标准：计划文档已创建

## 归档模式

### 1. 更新阶段 → 完成

总览文档 `项目阶段: 完成`。

### 2. 知识反哺

回顾 CHANGELOG、ADR、里程碑总结，提炼可复用经验 → 写为永久笔记 → `10_领域/<领域>/`。

- 完成标准：至少 1 条反哺笔记

### 3. 归档

项目文件夹移入 `90_归档/`，总览 `项目阶段: 归档`。

- 完成标准：项目已移出 `20_项目/`

## Gotchas

- 立项时跳过外部链接文档 → 后续资源散落，创建总览时一并建
- 把「项目计划」当作开发计划直接编码 → 仍须走拷问 → PRD → 拆 Issue
- 归档前没做知识反哺 → 项目经验随文件夹沉底，先提炼再移动
