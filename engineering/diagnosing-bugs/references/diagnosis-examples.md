# 诊断示例

## 稳定 bug

```text
现象：导入 CSV 时日期列偶发解析失败
1. 红色反馈环：用出错文件写一个单测，稳定失败
2. Mutation diff：把解析函数改成直接返回固定值，测试变绿 → 覆盖有效
3. 最小化：二分到某一行含 "2026/11/13" 与空格的组合
4. 假设：格式串未处理空格 / 时区
5. 埋点：打印解析前的原始字符串与格式串
6. 修复：trim 后再解析；补一条含空格的回归用例
```

## 偶发 bug

```text
现象：并发写入时偶发主键冲突
1. 红色反馈环：循环 1000 次并发写入，稳定复现
2. Mutation diff：把插入改成 upsert，冲突消失 → 覆盖有效
3. 最小化：降到 2 个并发 + 固定 sleep 顺序
4. 假设：检查-写入非原子 / 事务隔离级别
5. 埋点：记录每次插入前的查询结果与事务 ID
6. 修复：改为唯一约束 + upsert；补并发回归测试
```

## 性能回归

```text
现象：列表页 p95 从 200ms 涨到 1.2s
1. 红色反馈环：基准脚本固定数据集，记录 p50/p95/p99
2. Mutation diff：回退可疑 commit，p95 恢复 → 定位有效
3. 最小化：固定数据量与查询条件
4. 假设：N+1 查询 / 缺索引 / 序列化开销
5. 埋点：SQL 计数与耗时、序列化耗时
6. 修复：批量查询 + 索引；补基准脚本为回归用例
```

## 反例

| 写法 | 问题 |
|---|---|
| "应该是缓存问题" 直接改缓存 | 没有证据，可能引入新问题 |
| 测试红但没验证 mutation | 假红，修复可能无效 |
| 修复后删掉复现脚本 | 无法防复发 |
| 性能只看平均值 | 尾部延迟被掩盖 |
