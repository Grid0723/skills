# 内部机制与辅助工具

本文档基于 `tqcenter.py` 源码，解析框架内部的**生命周期管理**、**分页机制**、**股票代码体系**和**辅助工具函数**。

---

## 一、生命周期管理

### 初始化流程

```
tq.initialize(path) → _auto_initialize() → DLL.InitConnect() → 获取 run_id
```

- `tq.initialize(__file__)` 是手动初始化入口，设置 `_connection_path` 后自动调用 `_auto_initialize()`
- 每次 API 调用开头也会自动调用 `_auto_initialize()` — 若已初始化则跳过
- 初始化成功后会注册 `weakref.finalize` 和 `atexit.register` 双重保障，确保进程退出时自动关闭连接

### 重连机制

当 API 返回 `ErrorId` 为 `'6'` 或 `'7'` 时，框架自动调用 `_reInitialize()`，将 `_initialized` 置 `False`，下次 API 调用时自动重建连接。

### 关闭连接

- `tq.close()` — 主动关闭，调用 `DLL.CloseConnect(run_id, run_mode)` 并解注册回调
- **注意**：源码中部分校验失败时会在抛异常前自动调用 `tq.close()`

## 二、错误码体系

| ErrorId | 含义 | 框架行为 |
|---------|------|---------|
| `'0'` | 成功 | 正常返回数据 |
| `'6'` | 连接异常 | `_reInitialize()` 自动重连，返回空数据 |
| `'7'` | 数据异常 | `_reInitialize()` 自动重连，返回空数据 |
| `'12'` | 同名策略已运行 | 打印提示信息，run_id 仍有效，可继续工作 |
| `'19'` | 返回数据过大 | 仅公式批量调用时触发，部分数据截断，打印警告 |
| `'20'` | **致命错误** | `raise SystemExit` 立即终止程序（先尝试 `tq.close()`） |

> `_json_loads_with_errorid_guard()` 在每次 JSON 解析时自动检测 ErrorId=20，命中则终止进程。

## 三、分页机制

### 3.1 RPC 级分页（通用）

`_call_rpc_json_paged()` 处理一般接口的分页返回：
1. 首次调用返回 `TPythPaged: true` 标志
2. 使用 `page_token` + `page_index` 逐页拉取
3. 自动拼接 `page_data` 字符串，最后 `json.loads()` 得到完整对象

```
首请求: {"id": run_id, "type": N, ...}  →  {TPythPaged: true, page_data: "...", total_pages: 3, page_token: "xxx"}
页2请求: {"id": run_id, "_tpyth_page_token": "xxx", "_tpyth_page_index": 1}  →  {TPythPaged: true, page_data: "..."}
最终: json.loads(page_data_1 + page_data_2 + page_data_3)  →  完整结果
```

### 3.2 K 线股票级分页

`_call_kline_json_all_pages()` 处理 `get_market_data` 的批量股票分页：
- 首次请求含 `stock_page_index: 0` 和 `stock_page_size: 100`
- 返回 `KlinePaged: true` 后，按 `next_stock_page_index` 游标继续拉取
- 游标未前进时抛异常（版本不一致）
- 自动合并每页的 `Value`（股票数据）和 `Errors`

```
第1页: stock_page_index=0, stock_page_size=100  →  next_stock_page_index=100
第2页: stock_page_index=100                   →  next_stock_page_index=200
...
```

### 3.3 专业数据股票级分页

`_call_pro_data_json_all_pages()` 处理专业数据接口的分页：
1. 首次返回 `ProDataPaged: true` 和 `stock_total_pages`
2. 按 `stock_page_index: 0 ~ stock_total_pages-1` 循环拉取
3. 自动合并每页的 `Value`

## 五、时间格式转换

### `_convert_time_format(start_time)`

```python
# YYYYMMDD → 'YYYY-MM-DD HH:MM:SS'
_convert_time_format('20260101')  # → '2026-01-01 00:00:00'

# YYYYMMDDHHMMSS → 'YYYY-MM-DD HH:MM:SS'

# 空字符串 → ''（在 count>0 模式下 start_time 为空）
_convert_time_format('')  # → ''
```

### count 参数对时间的特殊处理

    start_time_fmt = ''
    end_time_fmt = _convert_time_format(end_time)

### 6.4 `tq._calculate_forward_factors_from_dividends()` — 计算前复权因子

```python
@classmethod
def _calculate_forward_factors_from_dividends(
    cls, df_factors: pd.DataFrame, price_series: pd.Series
) -> pd.Series:
```

- 从除权除息数据 + 价格序列计算前复权调整系数
- 公式：`调整系数 = 除权除息价 / 前收盘价`
- 其中 `除权除息价 = (前收盘价 - 每股分红) / (1 + 送股比例 + 配股比例)`
- 返回 `pd.Series`，索引为除权除息发生日期

## 七、`tq.print_to_tdx()` 内部路径逻辑

`print_to_tdx()` 用于将 DataFrame 导出为通达信客户端面板：

1. **自动推算通达信根目录**：`Path(__file__).resolve().parents[1]`（从 `tqcenter.py` 向上两级）
2. **生成 XML 文件** → 移动到 `T0002\cloud_cfg\`
3. **生成 JSON 数据文件** → 移动到 `T0002\cloud_cache\list\`
4. **生成 SP 配置文件** → 移动到 `T0002\pad\`
5. 自动处理日期格式化、数值处理、编码（XML/SP 用 GBK，JSON 用 UTF-8）

## 八、数据格式化内部流程

### `_fast_format_kline_data()` 核心逻辑

1. 收集所有股票的所有时间戳，构建统一的 `DatetimeIndex`
2. 对每个字段，创建 `np.full((n_time, n_stocks), np.nan)` 的 numpy 数组
3. 按 timestamp→index 映射填充数据
4. 若 `fill_data=True`，向前填充空值
5. 返回 `Dict[str, pd.DataFrame]`

### `_fast_format_tick_data()` 核心逻辑

1. 对每只股票独立处理（不跨股票合并时间）
2. 按 dtype 推断创建 numpy 结构化数组
3. 返回 `Dict[str, np.structured_array]`
