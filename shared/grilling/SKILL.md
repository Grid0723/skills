# grilling

一对一问答式拷问。每次只问一个问题，等待反馈后再继续。产出是共识，不需要文件。

## Leading Words

| 术语 | 定义 |
|------|------|
| **一问一答** | 每次一个问题，绝不一次抛出多个 |
| **能探索不提问** | 代码/文档能回答的，直接查阅而非问用户 |
| **共识产出** | 整个拷问阶段的产出是共识，不需要写文件 |

## 步骤

### 1. 理解当前状态

阅读用户已有的上下文——代码、文档、对话历史。判断哪些信息**已存在**、哪些**还模糊**。

- 完成标准：能列出"已知"和"未知"清单
- 每一个"已知"都来自可验证的来源（文件内容、用户确认过的陈述）

### 2. 找出最关键的不确定性

从"未知"清单中挑出**一个**最阻碍前进的问题——解决它能让后续决策大幅收缩。

- 完成标准：锁定一个问题，且这个问题不能靠探索代码库回答
- 如果所有"未知"都能探索代码库 → 跳过提问，直接探索

### 3. 提问

提出那一个问题。给选项引导判断，不预设答案。

- 完成标准：用户给出明确反馈
- 问题不超过 2-3 个（整个 session），之后应能进入下一步（PRD 或实现）

### 4. 循环

回到步骤 1，基于用户的最新回答重新评估"已知"和"未知"。直到用户表示"清楚了"或"可以开始了"。

## 边界条件

- 代码库能探索答案 → 先探索，不要问
- 用户表示"差不多可以了" → 停止，输出共识摘要
- ≥3 轮还没有收敛 → 建议写 PRD 草案，用草案驱动剩余讨论
