# 词汇表 — 写出优秀 Skill 的领域模型

本词汇表定义了"是什么让一个 skill 变得优秀"的领域模型。Skill 的存在意义是**从随机系统中拧出确定性**——根源美德是**可预测性**，下列每一个术语都是撬动它的杠杆。这是 `writing-great-skills` 的公开参考。

术语按轴分组：**调用轴**——skill 如何被触及；**信息层级轴**——skill 的内容如何排列；**引导轴**——如何塑造 Agent 的运行时行为；**裁剪轴**——如何让 skill 保持精简。每个**失败模式**放在治愈它的杠杆旁边，标注 _失败模式_。

任何定义中的**加粗术语**均在本词汇表中有独立词条。

---

## 根源美德

### 可预测性（Predictability）

Agent 在每次运行中采取相同的过程——相同流程，而非相同输出（头脑风暴 skill 应可预测地分叉）。所有其他术语服务的根源美德。

_避免使用_：一致性、可靠性、鲁棒性

---

## 一、调用轴（Invocation）

### 模型调用（Model-Invoked）

保留**描述**字段的 skill，Agent 可自主触发，其他 skill 可引用。人类仍可手动输入其名称。为可发现性支付**上下文负载**——每轮常驻。

_避免使用_：能力、工具

### 用户调用（User-Invoked）

**描述**被剥离的 skill——Agent 不可见，仅人类输入名称可触及，其他 skill 无法引用。零上下文负载，消耗**认知负载**。

_避免使用_：过程、工作流、命令

### 描述（Description）

Skill 的机器可读触发器，顶层**上下文指针**。其存在本身就是调用轴：保留 → 模型调用；删除 → 用户调用。模型调用 skill 的上下文负载来源。

_避免使用_：frontmatter、摘要

### 上下文指针（Context Pointer）

Agent 上下文中持有的引用，命名上下文外的材料并编码触发条件。**描述**是顶层指针（上下文窗口→skill）。措辞而非目标决定了触及的时机与可靠性。必须命中但措辞软弱的目标是方差 bug：先修措辞，失败后才内联。

_避免使用_：链接、引用、导入

### 上下文负载（Context Load）

模型调用 skill 对上下文窗口征收的成本——描述常驻，消耗 token 和注意力。用户调用 skill 免于此负载。拆分更多模型调用 skill 的刹车。

_避免使用_：token 成本、上下文膨胀

### 认知负载（Cognitive Load）

用户调用 skill 对人类征收的成本——人类必须记住哪些 skill 存在、何时取用（人类即索引）。不须最小化：这是人类代理权的代价。在判断重要处付出，不需要处移除。

_避免使用_：人工索引、负担、心智开销

### 路由 Skill（Router Skill）

一个用户调用 skill，指向其他用户调用 skill——命名每项并说明何时取用。只能提示，不能触发它们（用户调用无描述，无可触及）。用户调用 skill 倍增时治愈认知负载。

_避免使用_：分发器、菜单、注册表

### 粒度（Granularity）

切割 skill 的精细程度。两把刀：按**调用**切割——有独立 Leading Word 时才拆模型调用 skill；按**序列**切割——某步骤的后续步骤需隐藏时拆开。更细的切割消耗两种负载之一。

_避免使用_：分块、模块化

---

## 二、信息层级轴（Information Hierarchy）

### 信息层级（Information Hierarchy）

Skill 内容按 Agent 需要紧迫程度排名的单一阶梯，由两次切割产生：内嵌/指针后，步骤/参考。层级：**步骤**（内嵌主级）→ **参考**内嵌（次要）→ **参考**公开（上下文指针后）。无步骤的 skill 仅用底部两层，可合法地为平级对等项。

_避免使用_：结构、组织、布局

### 步骤（Steps）

Agent 执行的有序动作——有步骤时为主层级，值得留在 SKILL.md 中。每步以**完成标准**收尾。可全步骤、全参考、或混合，与调用方式无关。

_避免使用_：工作流、指令、编排

### 参考（Reference）

Agent 按需查阅的材料——定义、事实、参数、示例、条件指令。有步骤时次要，无步骤时是全部内容。通过**上下文指针**触达，**渐进披露**的首选候选人。

_避免使用_：支持材料、文档、背景资料

### 外部参考（External Reference）

位于 skill 系统外的参考——普通文件，无描述，无步骤，不可调用，任何 skill 都可指向。共享参考无需独立触发的归宿，两个用户调用 skill 共享参考的唯一途径。

_避免使用_：文档、资源、知识库

### 渐进披露（Progressive Disclosure）

将参考沿阶梯下移——移出 SKILL.md 到指针后面。非主要 token 优化，而是保护**信息层级**的方式。由**分支**授权：披露仅部分分支需要的，内联所有路径都需的。

_避免使用_：懒加载、分块

### 共置（Co-location）

将 Agent 需一次性使用的材料放在同一标题下——定义、规则、警告相邻——读一部分就自然带来邻居。区别于**复制**——复制是同一含义在两处，散落是单一含义分裂在多处。

_避免使用_：分组、聚类、内聚

### 分支（Branch）

Skill 的一种独特调用方式——不同运行走不同路径。有步骤的 skill 可能携多分支；线性 skill 无分支。

_避免使用_：路径、情形、分叉

## 三、引导轴（Steering）

### 锚定词（Leading Word）

模型预训练中已存的紧凑概念（_fog of war_、_tracer bullets_），以最少 token 锚定行为区域。在正文中锚定执行，在描述中锚定调用。自创也行但招募不到先验——优先取已存在的词。

_避免使用_：关键词、术语、主题

### 完成标准（Completion Criterion）

Agent 判定工作完成的标杆。**清晰度**抵御过早完成（能区分完成/未完成吗？），**要求度**设定腿脚工作（多彻底？）。最强标准既可检查又穷尽。也约束无步骤 skill 的平级参考。

_避免使用_：完成条件、退出条件、停止规则

### 腿脚工作（Legwork）

Agent 步骤内部的幕后工作——读文件、探索、挖掘所需而不推卸给用户。不写成独立步骤，潜藏措辞中，Agent 控制。由锚定词或要求穷尽的完成标准提升。

_避免使用_：范围、努力、勤勉、覆盖

### 后续步骤（Post-Completion Steps）

当前步骤后的步骤。可见时拉 Agent 入过早完成。防御：拆分隐藏——仅在真实上下文边界中有效。

_避免使用_：视野、战争迷雾

### 过早完成（Premature Completion）

_失败模式。_ 步骤未真完成即结束，注意力滑向"已经完成了"。步骤间失败——需步骤才能发生。两股力拔河：可见后续步骤（前拉）vs 完成标准清晰度（抵抗）。防御按序：先锐化标准（廉价局部）；不可削减模糊且观察仓促时，才拆分隐藏。

_避免使用_：过早关闭、仓促、抄近路

### 否定句（Negation）

_失败模式。_ 用禁止来指引适得其反——告诉 Agent "不要X"将 X 拖入上下文让它更易触及。其锚定词就是那头大象。解药：正向描述目标行为。仅作无法正向表述的硬守卫时保留，配以"应当做的"。

_避免使用_：反讽反弹、不要提示、粉红大象

## 四、裁剪轴（Pruning）

### 单一事实源（Single Source of Truth）

每种含义只存一个权威位置。**复制**是对它的违反。

_避免使用_：家、规范位置

### 关联性（Relevance）

一行是否仍与 skill 做的事相关。失去关联或因不承担任务，或因漂移过时。更短 skill 更易保持关联。区别于 **No-Op**：关联性问题不同。

_避免使用_：称职线、陈旧度、新鲜度

### 复制（Duplication）

_失败模式。_ 相同含义在多处存在。消耗维护、token，膨胀优先级超过真实排名。锚定词的意外反面——锚定词重复词例，不重复含义。

_避免使用_：重复、冗余

### 沉积（Sediment）

_失败模式。_ 陈旧层次堆积，"添加安全、移除危险"。无裁剪纪律的 skill 的默认命运。关联性的缓慢侵蚀。

_避免使用_：增长、膨胀、陈腐、腐朽

### 膨胀（Sprawl）

_失败模式。_ Skill 纯粹太长——即使每行都活都唯一。伤害可读性、可维护性，浪费 token。解药：信息层级 + 按分支或序列拆分。区别于沉积和复制。

_避免使用_：臃肿、长度、尺寸、冗长

### No-Op

_失败模式。_ 一行 Agent 默认就会遵守的指令——付费说废话。测试：删掉后行为改变吗？完全可关联却仍是 No-Op。弱锚定词（_be thorough_ 当 Agent 已足够仔细）是 No-Op；解药是更强词（_relentless_），非换技巧。

_避免使用_：冗余指令、重述显而易见、啰嗦
