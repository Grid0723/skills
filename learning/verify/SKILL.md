# verify

质量控制环节（贯穿 Local → Global）。防止"漂亮但不正确"的地图。

## Leading Words

| 术语 | 定义 |
|------|------|
| **认识论纠错** | 区分事实/观点/推论，确保概念定义一致、关系有证据 |
| **打回重挖** | 验证不通过 → 回到 dig 重新深挖，附疑点清单 |

## 步骤

### 1. 来源核查

- 结论是否有权威来源支撑？来源可信度如何？
- 完成标准：来源分级完成

### 2. 冲突检测

- 不同来源对同一概念/关系是否冲突？冲突点逐一记录
- 完成标准：冲突点已列出

### 3. 性质区分

- 每条结论是事实、观点还是推论？逐一标注
- 完成标准：结论性质已标注

### 4. 定义一致性

- 同一概念在不同来源中定义是否一致？（警惕"同概念异名/异概念同名"）
- 完成标准：定义差异已核对

### 5. 证据检查

- 每条语义关系是否有证据支撑？是否存在过度概括？
- 完成标准：无证据/过度概括项已标出

### 6. 判定

- 全部通过 → 结论可用
- 有疑点 → 打回 dig 重挖，附疑点清单
- 完成标准：判定结果已输出

## 参考

| 规则 | 说明 |
|------|------|
| 漂亮≠正确 | AI 可能把错误知识汇聚成看起来非常漂亮的地图 |
| 工程机制 | 验证是 Agent 学习流程的可靠性保障（非 Novak 理论第五机制） |

## 边界条件

- 疑点无法解决 → 标注"待考证"，不阻塞整体进度
