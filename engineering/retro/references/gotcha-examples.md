# Gotcha 写法参考

## 好的 Gotcha

具体、可执行、能阻止重复犯错：

- 用户说"整理一下"时直接移动文件，跳过 `classify` → 先确认归属领域，再 `organize`。
- 剪藏提炼完成后把原件留在收集箱 → 移入 `90_归档/剪藏/`，收集箱只进不留。
- 把 Fabric 的 `项目计划.md` 当作现成 PRD → 项目计划只是拷问素材，仍须完整走 PRD 与拆 Issue。
- 对未归位的笔记调用 `distill` → 先检查文件已在 `10_领域/` 或 `20_项目/`。
- 两个审查子 agent 共用上下文 → 各自独立上下文，报告不合并。

## 坏的 Gotcha

| 写法 | 问题 |
|---|---|
| "注意规范" | 没有具体动作，等于没写 |
| "不要犯错" | 不可执行，无法判断是否违反 |
| 复述正常步骤 | 占篇幅，不提供新信息 |
| 一次写 10 条 | 超过工作记忆，后续不会读 |
| 没有触发场景 | 不知道什么时候该想起它 |

## 归并规则

同一现象出现多次时合并为一条，用「→」连接原因与做法：

```markdown
- 归位后忘记提示提炼 → organize 结束时固定提示 distill
```

不要写成两条（"忘记提示" + "要提示提炼"），会稀释信号。
