# project-plan

创建按功能模块分组的任务清单，写入 `项目计划.md`。

## Leading Words

| 术语 | 定义 |
|------|------|
| **功能模块** | 任务按功能分组而非按时间线，每个模块独立可验证 |
| **#项目/<名> 标签归属** | 任务用 `#项目/<名>` 标签归属到具体项目 |

## 步骤

### 1. 确认项目范围

读取项目总览，与用户确认功能范围。

- 完成标准：功能模块列表已确认

### 2. 生成任务清单

在 `20_项目/<项目名>/` 下创建 `项目计划.md`：

```markdown
## 项目计划: <项目名>

### 模块 A
- [ ] 任务描述 #项目/<项目名>
- [ ] 任务描述 #项目/<项目名>

### 模块 B
- [ ] 任务描述 #项目/<项目名>
```

- 每个任务使用 `#项目/<项目名>` 标签归属
- 任务粒度：可在 1-2 个 session 内完成

- 完成标准：计划文档已创建

## 进入开发衔接

> [!warning] 项目计划 ≠ PRD/开发计划
> `项目计划.md` 是**项目管理维度的任务清单**（Obsidian 看板/里程碑用），**不替代**代码仓库中的 PRD（seam/范围/风险标注）与开发计划（tracer bullet 垂直切片）。项目进入正式编码时，仍须在代码仓库走 Grid 完整流程：**拷问 → PRD → 拆 Issue → 编码**——拷问阶段不可跳过，本计划仅作为 Grid 拷问的输入素材（验证需求完整性、拷问边界条件）。
