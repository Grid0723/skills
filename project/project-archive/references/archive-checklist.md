# 归档全流程检查清单

## 阶段 1：知识反哺

- [ ] 回顾项目 CHANGELOG——提取可复用的方法论
- [ ] 回顾项目 ADR——提取值得记住的决策理由
- [ ] 回顾里程碑总结——提取"如果再来一次会怎么做"
- [ ] 将每条可复用知识写为独立永久笔记 → `10_领域/<领域>/`
- [ ] 每条反哺笔记标注信源：`参见: [[20_项目/<项目名>/总览]]`

## 阶段 2：归档确认

- [ ] 确认所有代码已提交/合并
- [ ] 确认所有外部链接文档已更新最后状态
- [ ] 确认项目产出的文章/作品已移至 `10_领域/` 或公开发布
- [ ] 向用户确认："项目 `<项目名>` 即将归档。是否有需要保留但尚未提取的内容？"

## 阶段 3：物理归档

- [ ] 总览文档 `项目阶段` → 先设为 `完成`，确认无误后 → `归档`
- [ ] 移动项目文件夹 → `90_归档/<项目名>/`
- [ ] 更新 `20_项目/项目看板.md`——移除该项目条目
- [ ] 在 `90_归档/归档索引.md` 中添加索引条目

## 反例：不完整的归档

| 错误 | 后果 |
|------|------|
| 跳过知识反哺直接归档 | 项目经验被封存——未来同类项目从零开始 |
| 归档前不确认遗漏 | 归档后再找材料要在 `90_归档/` 中搜索 |
| 不更新看板索引 | 项目看板中残留已归档项目——看板失真 |
