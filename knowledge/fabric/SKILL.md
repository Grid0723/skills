# Fabric

知识管理总编排器。接收用户操作意图 → 路由判断阶段 → 按 CODE 流程驱动原子 skill → 嵌入织网检测。

## Leading Words

| 术语 | 定义 |
|------|------|
| **生命周期分层** | 笔记从捕获到归档的完整旅程：收集箱→领域/项目→归档 |
| **嵌入检测（Embedded Detection）** | 归位/提炼完成后自动检子标签笔记数，触发织网提示 |
| **写作管道路由** | 输出阶段根据复杂度走 fragments→beats→shape→edit 的部分或全管道 |
| **挂靠（Attached）** | 项目管理是独立于阶段管道的原子技能组，挂靠 Fabric 下 |

## 阶段序列

```
捕获 → 分类 → 归位(检≥3建MOC) → 提炼(检≥5融合hub) → 输出(写作管道路由) → 织网(手动全量)
```

## 入口判定（加载后先做）

| 用户请求 | 判定 | 动作 |
|---|---|---|
| 保存链接 / 剪藏 / 灵感 | 捕获 | → capture |
| 消化 / 整理某篇 | 归位 + 提炼 | → classify → organize → distill |
| 清一下收集箱 | 批量归位 | 列清单 → 逐篇确认 → 循环 |
| 整理知识库 / 建 MOC | 织网 | → connect |
| 写文章 / 出稿 | 输出 | → express |
| 与笔记无关（代码/环境/问答） | 不适用 | 说明不属于 Fabric 并退出 |

边界：一次会话只推进一篇或一批笔记，不跨阶段跳步；用户要求跳步时，先说明缺失的前置条件再执行。

## 步骤

### 1. 捕获——引用 capture

用户提供 URL/灵感/剪藏 → 加载 `capture` skill。捕获不加判断，不求全。

- 完成标准：笔记已创建在 `00_收集箱/`，`状态: 待整理`
- 如果用户在对话中已提供内容 → 直接捕获
- 如果是灵感速记 → `类型: 速记`
- 如果内容是**想法**（想做的事/想写的选题/待验证的假设/生活念头）且能写出一句最小验证动作 → 改写为 `类型: 想法` 进 `01_孵化/`（用 `_模板/想法模板.md`：`想法类型` + `孵化阶段` + `下一步` + `回访`，**不设** `状态` 字段）；写不出下一步的仍留在收集箱。规则见 `01_孵化/README.md`

### 2. 分类——引用 classify

加载 `classify` skill。判断笔记归属领域/项目。对照 9 领域表，不确 定的标 `待归类/`。

- 完成标准：归属方向已向用户确认

### 3. 归位——引用 organize

加载 `organize` skill。物理移动+更新标签，`状态: 已归位`。

完成后**嵌入织网检测**：查询该笔记关联子标签下笔记数 ≥3 → 提示建子主题 MOC（`类型: 索引`）。

- 完成标准：文件已移入领域/项目目录，frontmatter 已更新

### 4. 提炼——引用 distill

加载 `distill` skill。四层渐进式总结——加粗→高亮→执行摘要。

完成后**嵌入融合检测**：查询子标签 ≥5 → 提示融合为整合 hub 笔记（`状态: 可输出`）。

- 完成标准：执行摘要已补充，提炼层次已应用，`状态: 已提炼`

### 5. 输出——引用 express

加载 `express` skill。检测写作意图，路由到写作体系：

| 用户意图 | 路由 |
|---------|------|
| 碎片/灵感 | `writing-fragments` |
| 有原料缺结构 | `writing-fragments` → `writing-beats` |
| 完整文章 | `fragments` → `beats` → `shape` → `edit-article` |
| 精炼已有文章 | `edit-article` |

- 完成标准：用户确认写作管道，第一个写作 skill 已加载
- 不承担开启新项目的职能

### 6. 织网——引用 connect（手动触发）

用户主动要求全量扫描时加载 `connect` skill。L1-L4 递进检查。

- 完成标准：扫描完成，MOC/hub/双链建议已输出

## 项目管理——挂靠触发

项目管理的 5 个原子 skill 独立于阶段管道，按需手动触发：

| 用户说 | 加载 |
|--------|------|
| "新建项目" | `project-init` → `project-plan` |
| "更新里程碑"、"回顾进度" | `project-review` |
| "加个外部链接" | `project-links` |
| "归档项目" | `project-archive` |

## 内部引用

| 阶段 | 引用的原子 skill | 嵌入检测 |
|------|-----------------|---------|
| 捕获 | `capture` | — |

## 提交信息模板

每批处理完成后，提交信息按以下格式书写，便于用 `git log --grep` 追溯：

`docs: <动作>《<笔记名>》—— <阶段> + <可选结果>`

示例：
- `docs: 消化《稳定币牌照》—— 归位 交易投资 + 提炼 L4`
- `docs: 清理收集箱—— 归位 4 篇，归档 2 篇`

## Gotchas

- 用户说「整理一下」时直接移动文件、跳过分类 → 先 `classify` 确认归属，再 `organize`
- 归位阶段写 `状态: 已消化` → 只能写 `已归位`；提炼完成才写 `已提炼`
- 剪藏提炼后原件留在收集箱 → 移入 `90_归档/剪藏/`，收集箱只进不留
- 一次会话连续处理多批笔记 → 一批处理完先落状态并提交，再开下一批
