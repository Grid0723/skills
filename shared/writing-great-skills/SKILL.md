# writing-great-skills

Skill 的存在意义是**从随机系统中拧出确定性**。**可预测性（Predictability）**——Agent 每次运行采取相同的_过程_，而非产生相同的输出——是根源美德；每一个杠杆都服务于它。

**加粗的术语**定义在 [`GLOSSARY.md`](00_收集箱/待归类/writing-great-skills/GLOSSARY.md) 中。

## 一、调用轴（Invocation）

两种选择，支付不同的成本：

- **模型调用（Model-Invoked）** — 保留 **描述**，Agent 可自行触发，其他 skill 可引用它。支付**上下文负载（Context Load）**——描述常驻上下文窗口。机制：不设 `disable-model-invocation`。
- **用户调用（User-Invoked）** — 剥离描述，仅人类手动触发，其他 skill 无法引用。零上下文负载，但消耗**认知负载（Cognitive Load）**——人类必须记住它。机制：`disable-model-invocation: true`。

只有 Agent 必须自行触及、或另一 skill 必须引用时，才选模型调用。否则做用户调用，不付上下文负载。

当用户调用 skill 多到记不住时，由**路由 Skill（Router Skill）**治愈：一个用户调用 skill 命名其他 skill 并说明何时取用。

## 二、如何写描述

模型调用的描述承担两项工作——说明 skill 是什么，列出触发它的**分支**。描述比正文更需要不惜代价地修剪：

- **前置 Leading Word** —— 描述是 Leading Word 发挥调用功能的地方
- **每条分支一个触发短语** —— 同义词是**复制**，折叠掉。只保留真正不同的分支
- **删掉身份描述** —— 已经在正文里，描述只留触发短语

## 三、信息层级轴（Information Hierarchy）

Skill 的内容按 Agent 需要的紧迫程度排名为单一阶梯：

1. **内嵌步骤（In-skill Step）** — `SKILL.md` 中有序动作，主层级。每一步以**完成标准**收尾
2. **内嵌参考（In-skill Reference）** — `SKILL.md` 中的定义、规则、事实，按需查阅
3. **外部参考（External Reference）** — 推入独立文件的参考，通过**上下文指针**触达

一个没有步骤的 skill 仅用底部两层——通常是合法的平级对等项（如审查清单），不是坏味道。

**渐进披露（Progressive Disclosure）** 是沿阶梯下移——移出 `SKILL.md` 进入链接文件。最干净的披露测试是**分支**：内联每条路径都需的内容，把仅部分分支需要的推到指针后面。

**共置（Co-location）** 决定了放哪里之后_旁边放什么_：概念的定义、规则和警告放在同一个标题下。

### 共置 vs 复制——精妙区分

| | 共置 (Co-location) | 复制 (Duplication) |
|---|---|---|
| 发生了什么 | 单一含义的一组属性散落在文件中 | 一个含义同时出现在两个位置 |
| 修复方式 | 将散落的属性**移到同一标题下** | 保留**一处权威位置**，删除另一处 |
| 典型症状 | 定义在 §3、规则在 §6、警告在 §9——读全需跳三次 | 提交规范写在 `git-commit-guide` 和项目 `AGENTS.md` 两处 |
| 反例 | 把本应独立的概念硬塞在同一标题下（变成巨型段落） | 把两条"看起来一样但语义不同"的规则合并（丢失精度，见 **No-Op**） |

## 四、何时拆分

**粒度**是切割 skill 的精细程度。两把刀：

- **按调用切割** — 有独立 Leading Word 应单独触发，或另一 skill 必须引用时，拆出模型调用 skill。支付上下文负载
- **按序列切割** — 某步骤的**后续步骤**诱惑 Agent 草草结束时，拆开序列。清除后续步骤的暴露

## 五、引导轴（Steering）

### Leading Word

模型预训练中已存的紧凑概念，以最少 token 锚定整块行为区域。在正文中锚定**执行**——每次出现都触及相同行为。在描述中锚定**调用**——同样的词出现在提示语中会提高触发可靠性。

寻找将重述折叠为词例的机会。例如：
- "快速、确定性、低开销" → _tight_
- "一个你信任的循环" → _red_

### 寻找折叠机会——方法论

在编写或审查一个 skill 时，逐段扫描以下模式：

1. **多用形容词描述一个品质** → 折叠为一个 Leading Word
2. **用一句话解释"目的"而非用词例锚定** → 折叠为一个 Leading Word
3. **同一含义在三个地方出现** → 折叠为 Leading Word + 重复词例

更多真实案例：
- "代码要短、改动要局部、不要影响无关模块" → **surgical**（手术刀式改动）
- "每完成一步就要验证，不等到最后才检查" → **verify-as-you-go**（步步验证）
- "写完文档后不只自己看，要站在读者角度重读" → **fresh-eyes**（换一双眼睛）

每一次折叠赢两次：更少的 token，_以及_一个更锋利的钩子让 Agent 挂接其思考。假设每个 skill 都携带着能被 Leading Word 退役的重述——去找到它们。

### 完成标准

告诉 Agent 工作完成的判定条件。**清晰度**抵御过早完成（Agent 能区分完成/未完成吗？），**要求度**设定腿脚工作（多彻底才算够？）。最强的标准既可检查又穷尽。

### 腿脚工作

Agent 在步骤内部的幕后工作——读文件、探索代码、挖掘所需而不推卸给用户。潜藏在措辞中，由 Agent 而非 skill 控制。

### 后续步骤的可见性风险

可见的后续步骤把 Agent 拉入过早完成。防御：拆分序列隐藏它们——但仅在真正的上下文边界中有效。

## 六、裁剪轴（Pruning）

- **单一事实源** — 每种含义只存一处权威位置
- **关联性** — 每行仍与 skill 所做的事相关吗？
- **No-Op 逐句测试** — "删掉这句话，Agent 的行为会改变吗？" 通不过就删掉整句，不要修剪词例。要激进

### No-Op 逐句测试——执行方法

对 SKILL.md 中的每个句子（句号到句号，不是段落）逐个执行：

1. **删掉这句话。**
2. **重新运行这个 skill。** Agent 的行为变了吗？
3. 没变 → 这句话是 No-Op。**删掉整句**，不要试图"修剪几个词让它变有用"。
4. 变了 → 保留。

这个测试是**模型相对的**，不是读者相对的。两个人对"是不是 No-Op"有分歧时，分歧的是默认行为——通过实际运行 skill 来裁定，而非讨论。

弱 Leading Word 是最常见的 No-Op 来源：`be thorough`（Agent 本来就不马虎）是 No-Op；换成 `relentless`（不留死角）可能就不是。**不是换技巧——是换更强的词。**
- **膨胀** — skill 纯粹太长。解药是信息层级 + 按分支或序列拆分

### 失败模式诊断清单

| 失败模式 | 诊断标准 | 解药 |
|---------|---------|------|
| **过早完成** | 步骤未真完成即结束 | 先锐化完成标准；不可削减模糊时拆分隐藏后续步骤 |
| **复制** | 相同含义在多处出现 | 保留一处权威位置，其余删除 |
| **沉积** | 陈旧层次堆积 | 定期裁剪：添加同时移除 |
| **膨胀** | 纯长度问题 | 披露参考到指针后面，按分支或序列拆分 |
| **No-Op** | 删掉后行为不变 | 删掉整句；或换更强 Leading Word |
| **否定句** | 用"不要X"来约束 | 正向描述目标行为 |

## 七、本体系专属约定

### 双脊椎分工

| 脊椎 | 管辖 | 编排器 |
|------|------|--------|
| Grid | 软件开发项目 | Grid 编排器 |
| Fabric | Obsidian vault 内全部内容 | Fabric 编排器 |

Skill 限归属一条脊椎或全局共享层。

### 归属判断

```
① 被两条脊椎共享？→ 全局共享层 (.agents/skills/)
② 多个项目通用？  → 全局共享层
③ 绑定特定技术栈？ → 项目热插拔层 (项目仓库 .agents/skills/)
```

### 触发策略阈值

| 条件 | `disable-model-invocation` |
|------|---------------------------|
| 编排器 / 有副作用 / 需人类判断 | `true` |
| 纯分析/只读 / 背景被动 | `false` |

### 交互节奏

- **一问一答型**：每次一个问题（拷问、分类）
- **逐段引导型**：解释→选项→确认→下一步（PRD、拆 Issue）
- **即时应答型**：即时纠偏，不等待（审查、织网检测）

共通：能探索不提问；不超过 2-3 个澄清问题；大决策拆小问题。

### 文件产出铁律

1. **审批门**：PRD/开发计划 → 展示草案 → 确认 → 写入
2. **即时写入**：ADR/术语表/配置 → 决定即写入
3. **极简产出**：ADR 一个段落，任务清单 30 秒可读完
4. **纯对话**：拷问/分类 → 产出是共识

### Skill 创建检查清单

```
□ Scope: 一句话描述边界
□ Trigger: description 含精确触发短语
□ Output: 用户可预判产出形态
□ Vocab: 定义 3-5 个 Leading Word
□ Layer: SKILL.md 含步骤+参考，外部参考放独立文件
□ Length: 不超过类型上限（primitive≤50 / 规范≤100 / 编排器≤200）
□ Positive: 全部正向描述
□ SSOT: 每种含义只存一处
□ No-Op: 逐句测试
□ Completion: 每步骤有清晰穷尽的完成标准
```
