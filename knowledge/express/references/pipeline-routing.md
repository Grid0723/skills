# 写作管道路由判断

## 复杂度→管道映射

| 用户输入 | 判断 | 路由 |
|---------|------|------|
| "帮我写一篇关于 A 股打新策略的文章" | 需要从零开始 | `fragments` → `beats` → `shape` → `edit` |
| "整理一下我收集的 ETF 交易碎片" | 有原料，缺结构 | `beats` → `shape` → `edit` |
| "这篇草稿帮我润色一下" | 有成品，要打磨 | `edit-article` |
| "记一下这个想法：布林带宽度压缩可以..." | 碎片采集 | `fragments` |
| "上次那个 ETF 碎片堆我准备好了，帮我编排" | 从碎片到结构 | `beats` → `shape` → `edit` |

## 管道跳步协议

用户可随时说：
- "就写到 fragments，先不继续" → 暂停管道
- "直接从 beats 开始，碎片我自己整理了" → 跳过 fragments
- "不用编辑，shape 完就行" → 跳过 edit-article

每个 skill 完成后，Fabric 输出阶段询问是否进入下一步。
